# 青年集体婚礼编排

编排多人婚典礼序、婚书与影像授权，避免现场错配。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括新人、联合主办单位、现场礼仪团队、影像与婚书制作方。

资料所依据的领域事实如下：

- 活动有五十对青年人才参加
- 婚典包含巡游、多个古礼环节和集体诵读婚书
- 现场同时展示电子婚书与实体婚书

## 编排服务

`src/orchestration.py` 提供 `WeddingOrchestrationService`，覆盖活动的授权、编排与现场变更：

- **逐项授权**：身份核验、伴侣关系、展示姓名、影像素材、礼服尺寸、仪式角色、巡游顺序、婚书版本、市集服务预约，缺少授权即不可登记对应资料；展示姓名经新人确认前，各环节只显示匿名编号。
- **变更传播**：撤回公开、姓名修订、替换素材、迟到跳序、双方取消参加、设备故障都会生成变更事件并传播到尚未执行的环节；已完成环节保留冻结快照，已签署与已交付的婚书保留原记录。
- **视图最小化**：`couple_view` 让新人确认自己将如何被展示并查看变更结果；`staff_view` 按岗位只返回当前环节所需字段；`audit_overview` 供负责人核对五十对流程完整性与电子/实体婚书一致性，不含证件资料。
- **按期删除**：`retention_report` 列出每项授权的计划删除时间，`purge_expired` 删除到期或已撤回授权对应的资料。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。

```bash
python -m unittest discover -s tests -t .
```
